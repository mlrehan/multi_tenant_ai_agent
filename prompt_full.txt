# PROJECT CONTEXT

	Develop a production-ready, multi-tenant identity, authentication, and authorization system for an enterprise AI Assistant platform.

	The AI Assistant platform will serve multiple independent organizations.

	Each organization must operate inside its own isolated tenant boundary.

	The system must clearly distinguish between:

	1. Platform-level users
	2. Tenant-level users

	The authorization model must prevent accidental cross-tenant access while still allowing authorized platform operators to manage the complete platform.

# TENANT MEMBERSHIP MODEL

	A user account may belong to:

		* no tenant;
		* one tenant;
		* multiple tenants.

	A separate tenant membership must exist for each user-tenant relationship.

	The membership should include:

		* user ID;
		* tenant ID;
		* membership status;
		* invitation status;
		* joined date;
		* invited by;
		* default tenant indicator;
		* department;
		* team;
		* job title;
		* tenant-specific metadata;
		* assigned tenant roles;
		* last activity;
		* suspension information.

	The same user may have different roles in different tenants.

	Example:

	A user may be:

		* Tenant Administrator in Tenant A;
		* Analyst in Tenant B;
		* Read-Only User in Tenant C.

	Roles must never leak between tenant memberships.

# ACTIVE TENANT CONTEXT

	Every tenant-specific request must resolve an active tenant context.

	The tenant may be resolved through a secure and documented strategy such as:

		* tenant subdomain;
		* custom domain;
		* verified request header;
		* URL path;
		* authenticated tenant selection;
		* token claim combined with server-side membership validation.

	Do not trust a tenant ID merely because it is included in a JWT or request parameter.

	For every tenant request, validate:

		1. The user is authenticated.
		2. The tenant exists.
		3. The tenant is active.
		4. The user has an active membership in that tenant.
		5. The membership is not suspended or revoked.
		6. The requested resource belongs to the same tenant.
		7. The membership has the required role or permission.
		8. Additional ownership, team, department, or policy rules are satisfied.
